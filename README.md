# Predicting Student Dropout Risk with Machine Learning

Capstone project for the Post Graduate Diploma in Artificial Intelligence and Machine Learning.

Author: Einar Ramos Abuyuan

> Objective: identify students at risk of dropping out early enough for advisors to intervene before the problem escalates.

---

## 1. Project overview

This project frames dropout prediction as a binary classification problem using the UCI dataset "Predict Students' Dropout and Academic Success". The dataset contains academic, financial, and demographic indicators for 4,424 students and is used to predict whether a student will be classified as a dropout or not.

The repository includes the full analysis pipeline, model comparison scripts, fairness and explainability checks, and the final project presentations.

## 2. Results summary

The logistic regression pipeline is the primary model used for the final decisioning output. It meets the project success criteria for the dropout class:

| Metric | Target | Achieved |
| --- | --- | --- |
| Recall | >= 0.80 | 0.841 |
| Precision | >= 0.70 | 0.773 |
| AUC-ROC | >= 0.85 | 0.926 |
| Accuracy | — | 0.812 |

This model was selected because it balances strong predictive performance with interpretability, which is important for academic advising and intervention decisions.

## 3. Dataset

- Source: UCI Machine Learning Repository — "Predict Students' Dropout and Academic Success"
- Records: 4,424 students
- Features: 37 columns
- File: `data/raw/students_dropout_academic_success.csv`
- Data dictionary: `data/data_dictionary.md`
- Target: `target` (multi-class outcome, with dropout treated as the positive class in the modeling pipeline)

## 5. How to run the project

Requirements:

- Python 3.10+
- pip / conda environment

```bash
git clone https://github.com/Bunz825/student-dropout-prediction.git
cd student-dropout-prediction
pip install -r requirements.txt
python run_all.py
```

This runs the numbered scripts in `src/` in sequence and produces the trained models, saved metrics, and generated charts.

## 7. Notes

- The code is designed to run from the repository root without needing hard-coded absolute paths.
- Model artifacts and metrics are created during execution and are not all committed to version control by default.
- The project includes fairness and explainability work to ensure the model is not only accurate but also interpretable and ethically defensible.
